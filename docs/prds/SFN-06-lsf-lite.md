# SFN-06: lsf, the fast version of the same flow, for a one-hour live session on a Mac

| | |

| **Implementer model** | Sonnet |

## Purpose
`/lsf` replaces the old prose-only lightweight skill. It runs the owner's flow (brief, minesweep, research, experiments, tracer PRDs with UX stories first, MECE evals, blind build, QA, mechanistic review with the dolls, docs and drift) with the same stage names and file conventions as `/sf`, but needs only Python 3.9+ and git: no virtualenv, no solver, no Linux tools. The audience (Peak6) will watch telemetry and human-in-the-loop checkpoints, so the dashboard is the main screen. The owner expects about 60% of the hour on human-AI alignment steps (informed by research and experiments), about 20% on code review, the rest on build, QA and wrap-up.

## UX story (first)
As the owner in a live hour, I run `lsf init`, open the dashboard, and see the phase clock, a planned-versus-actual time bar for alignment, build and review, and any checkpoint waiting for me with a button to approve it. When I click a file in the nested diagrams my editor opens at the line. When the hour ends I can show the journey, the decisions I approved and how long each took.

## Required behaviour
Everything is a single standard-library Python file `skills/lsf/scripts/lsf.py` (Python 3.9 syntax and library only; no third-party imports; no `fcntl`, `flock`, `prlimit`, `/proc` or Linux-only calls) plus one offline HTML file `skills/lsf/assets/dashboard.html` and `skills/lsf/SKILL.md`. State lives in `.lsf/` and the project files below; nothing outside the project is written except by `install.sh`.

- **L-01 layout and install.** `skills/lsf/` holds `SKILL.md` (frontmatter `name: lsf`, `disable-model-invocation: true`), `scripts/lsf.py`, `assets/dashboard.html`, `assets/editor-links.js`, `scripts/eli12.py` (copies of the SFN-08/SFN-07 files, with a test that they are byte-identical to their sources when those exist), and `install.sh` (POSIX sh, macOS-safe: no GNU-only flags) that copies the skill to `${CLAUDE_SKILLS_DIR:-$HOME/.claude/skills}/lsf`, moves any existing different `lsf` there to `lsf.backup-<UTC timestamp>` first, and links `lsf` into `${LSF_BIN_DIR:-$HOME/.local/bin}` as a tiny `python3` wrapper. Running it twice changes nothing the second time and prints what it did.
- **L-02 commands.** `lsf init | phase | event | hitl | status | budget | serve | bundle | hooks | doctor | cost`, each with `--help`; exit 0 ok, 1 check failed, 2 usage, 3 refused by a human stop. All accept `--root DIR` (default: nearest git root, else cwd).
- **L-03 the stages.** `lsf init` writes `.lsf/profile.json` with `session_minutes` (default 60), the ordered phases and their groups: **align** = `0-intake` (brief), `1-sweep` (minesweep: core value and best practices), `2-research` (seeds), `3-experiments`, `4-prd` (tracer PRDs, UX stories first, one-page PRD), `5-evals` (MECE surface), `6-decide` (ADRs); **build** = `7-implement`, `8-qa`; **review** = `9-review` (dolls, Ponytail rubric, minesweeper lenses), `10-docs` (ELI12 + ADR sync + drift). Group weights default 0.60 / 0.20 / 0.20 for align / review / build, configurable, and must sum to 1.0 within 0.001 (else exit 2). Stage ids are an alias map to the sf stages (documented in SKILL.md) so events from both tools read the same.
- **L-04 phase clock.** `lsf phase start NAME` and `lsf phase end NAME [--verdict V] [--note T]` append events with timestamps; starting a phase while another is open ends the first with verdict `switched`; ending a phase not open exits 1. `lsf status` prints the open phase, elapsed minutes, open human stops and the next phase. Phase names outside the profile exit 2.
- **L-05 time budget.** `lsf budget [--json]` prints, per group, planned minutes (`session_minutes` x weight), actual minutes from closed and open phases (open phases counted to now), percent of plan, and an over/under flag; time with an open human stop is counted separately as `waiting on human` and reported, not hidden. Unknown (no phase yet) is `not measured`, never 0.
- **L-06 events (telemetry).** `.lsf/events.jsonl` append-only, one JSON object per line written with a single `O_APPEND` write: `at`, `stage`, `slice`, `phase`, `verdict`, `note`, `source` (`lsf`, `hook`, `agent`), optional `role`, `duration_s`, `sha` (HEAD or `unknown`). Notes are truncated at 2,000 characters, control characters replaced, secret-shaped values redacted, and a failed write prints `event not recorded: <reason>` to stderr without changing the command's exit code. `lsf event STAGE VERDICT [--note T] [--role R]` writes one by hand. `SF_EVENTS=off` and `LSF_EVENTS=off` disable writing.
- **L-07 human checkpoints.** `lsf phase end` for the phases `0-intake`, `1-sweep`, `2-research`, `3-experiments`, `4-prd`, `5-evals` and `6-decide` automatically opens a stop named `<phase>-review` with a `question` (one line given by `--ask`, default "Approve <phase>?"), an `artifact` path list (given by `--artifact`, repeatable) and `reason`. `lsf hitl request NAME --question Q [--artifact P]...`, `lsf hitl status [--json]` (exit 3 when any is open), `lsf hitl release NAME [--note T] [--by REF]` (records who and when; refuses unknown or already released). Stops are stored in `.lsf/stops.jsonl`, append-only with a SHA-256 chain per entry; `status` verifies the chain and reports a broken chain as `stop ledger failed verification` (exit 1), never as "no stops". While any stop is open `lsf phase start` exits 3 and prints the open stops, so the agent skill's rule "run `lsf hitl status` first" is also enforced by the tool. Checkpoints can be switched off per phase in the profile (`checkpoints`), and `lsf init --checkpoints align|all|none` sets the default. Release is a human act: `SKILL.md` forbids agents from releasing; the tool states it is a procedure, not proof of identity.
- **L-08 hooks (automatic telemetry).** `lsf hooks print` prints the Claude Code `hooks` JSON for `SubagentStop`, `Stop` and `PostToolUse` (matcher `Bash`, only for commands containing `git commit`), each calling `python3 <abs>/lsf.py hook <name>`; `lsf hooks install --project DIR [--apply]` shows a diff of `DIR/.claude/settings.local.json` and writes it only with `--apply`, merging without removing existing entries and idempotently; `lsf hooks uninstall --project DIR --apply` removes only its own entries. `lsf.py hook NAME` reads the JSON payload from stdin, writes an event (role from `agent_type` when present, tool name, a 200-character summary with secrets redacted) and ALWAYS exits 0 with no output, even on malformed input.
- **L-09 serve.** `lsf serve [--port 8765] [--open]` serves the dashboard on `127.0.0.1` only; a request with a non-localhost `Host` header gets 403. GET routes: `/` the dashboard, `/api/state` (all tabs' data plus runtime state, built per request), `/api/file?path=` (a UTF-8 text file inside the repo, max 1 MiB, never outside the root or through a symlink escape, never under `.git/`, `.lsf/` secrets or `.env*`), `/api/at?sha=` (historical tabs from `git show` at that commit). The one POST is `/api/hitl/release` taking `{name, note}`; it requires the header `X-LSF-Token` equal to a random token generated at server start and printed once in the terminal as part of the URL fragment (`http://127.0.0.1:PORT/#token=...`); a missing or wrong token gets 403 and no change. No other mutating route exists. `--open` uses `open` (macOS), `xdg-open` or `webbrowser`. The server does not log request bodies or the token.
- **L-10 dashboard tabs.** One offline file, no network resources, dark and light via `prefers-color-scheme`, usable at 390 px. Tabs: **Now** (open phase, planned-vs-actual group bars, open human stops each with its question, artifact links and an Approve button that calls the release route when a token is present, else shows the terminal command), **Telemetry** (event timeline, phase durations, human wait times per stop, agent stops, cost if logged, counts of pass/fail verdicts), **Research**, **Experiments**, **ADRs**, **PRD** (one-page journeys), **Architecture** (the nested dolls: embeds or links `docs/explorer/*.html`, each node's files open in the editor via `editorUrl`), **Docs** (the ELI12 index, each module page rendered, each entry linking to its source line), **Evals & bugs**, **Git** (commit list with a selector that reloads the historical tabs from `/api/at`). Every tab states `not available: <reason naming the path searched>` when it has no data; `available` never appears with zero items. File references everywhere use the editor links (SFN-08); the editor and workspace root come from `.lsf/profile.json` (`editor`, default `vscode`; `workspace_root` set by `init` to the absolute root) and may be changed in the dashboard header for the session.
- **L-11 same file conventions as /sf.** Tabs read the same artifacts the SFN-03 contract defines (`docs/prd/onepager.md`, `docs/slices/*/proposal.md`, `docs/prds/*.md`, `experiments/*/results.json` and `resolved.json`, `docs/adr/*.md`, `docs/bugs/*.md`, `docs/slices/*/qa-notes.md`, `docs/eli12/`, `docs/explorer/`). A parity test runs the lsf collectors and `factory.ops.collect` over the same fixture repository and requires equal items for the tabs both implement.
- **L-12 cost log.** `lsf cost add --usd X [--tokens N] [--model M] [--note T]` appends a `cost` event; `lsf cost summary` totals by model. Values are as the operator states them, labelled `manual`; nothing is estimated.
- **L-13 doctor.** `lsf doctor` checks Python is 3.9 or newer, `git` exists and the root is a repository, the port is free, `.lsf/` is writable, the editor name is known, `node` presence (informational only), and that no 3.10+ syntax or third-party import is present in `lsf.py` (self-check via `ast.parse(feature_version=(3, 9))`). Any failed check is FAIL and exit 1; it never reports PASS for a check it could not run.
- **L-14 agent skill text.** `SKILL.md` gives the flow in the owner's order with the stage alias map, the time split, the rule to run `lsf hitl status` at the start of each phase and stop on exit 3, to open a checkpoint instead of asking a question in chat, to record phase start/end, to write the artifacts the tabs read, to use the ELI12 format for docs, to use the dolls and the Ponytail rubric for review, and to never release a stop. It names model tiers as a profile choice (`models` in `profile.json`, optional) and does not hard-code any model name.
- **L-15 resource and safety.** No command reads more than 5 MiB of any one file into memory or lists more than 20,000 files; collectors skip `.git`, `node_modules`, `.venv`; the server holds no unbounded caches. Paths from the browser are validated like K-03. No command makes a network request.
- **L-16 nothing existing breaks.** The sf code, tests and evals are untouched except new files; `skills_sync.py check` still passes (it learns `lsf` as a repo skill).

## Acceptance
Graded by hidden evals (CLI via subprocess in tmp git repos; HTTP against `lsf serve` on an ephemeral port; static checks on the HTML; Python 3.9 syntax via `ast`). Write your own unit tests in `tests/lsf/`. Where a behaviour and a contract disagree, stop and report.
