# Requirements register

Every line of prose in [docs/BRIEF.md](BRIEF.md) is tracked here with its source line number. That includes narrative and business context, metadata, out-of-scope lists, judging criteria, deliverables and lines marked optional. A line that holds several sentences or obligations is split into rows that share the line number and carry a letter suffix (21a, 21b). Blank lines, horizontal rules and headings are not rows; headings supply the Section column. [docs/BRIEF.md](BRIEF.md) remains the source of truth. This register records how each line will be satisfied and does not replace it.

Coverage, types and dependencies are checked by `register.py check`; the build order below is generated by `register.py order --write`.

## Types

| Type | Meaning |
|---|---|
| Hard | Behaviour, data, invariant, measurable target or stack rule the system must satisfy. |
| Behaviour | User-visible flow, copy or UI that is not core logic. |
| Given | A premise the brief says to assume is true; the design may rely on it and documents where it does. |
| Constraint | A boundary: out of scope, prohibited, ignored or not judged. |
| Quality | A judging criterion with no pass/fail threshold; satisfied by a named artifact that demonstrates it. |
| Deliverable | An artifact to hand over. |
| Test | A test that must exist and pass. |
| Research | An investigation whose findings must be documented. |
| Optional | Explicitly optional; needs an in-or-out decision. |
| Context | Narrative, motivation, definition, example or metadata; the product and docs stay consistent with it. |

## Status

| Status | Meaning |
|---|---|
| unserved | Nothing produces it yet. |
| partial | Some evidence exists; Notes say what is missing. |
| satisfied | The Evidence column names the artifact that satisfies it. |
| blocked | Waiting on a named dependency (a decision, an asset, another row). |
